## 1. 系统架构

### 1.1 总体架构分层

系统采用云原生微服务架构，分为 7 个层次：

```
┌─────────────────────────────────────────────────────────────┐
│                     接入层 (Access Layer)                     │
│  Web Console │ Responses API + Chat Completions │ SDK │ CLI  │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                 网关与路由层 (Gateway & Routing)               │
│  API GW │ Responses Adapter │ 认证鉴权 │ 速率限制 │ 智能路由   │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                     控制面 (Control Plane)                    │
│  用户/团队 │ 计费服务 │ 端点管理 │ 模型注册 │ 负载均衡         │
│  模型评测 │ Prompt模板 │ 预算告警 │ 数据质量 │ 语义缓存        │
│  模型版本 │ 微调调度 │ A/B测试框架                            │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│               数据面 (Data Plane) — GPU 集群                  │
│  MultiEngineRouter（vLLM/SGLang/Custom/Mock）                │
│  专属端点实例池（HAMi GPU 资源隔离）                           │
│  批量推理工作节点 │ 微调训练集群                               │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                  调度与编排层 (Orchestration)                  │
│  Volcano Scheduler（Gang/Queue/Priority/Capacity）           │
│  HAMi Device Plugin（GPU Memory/Cores/Topology-aware）       │
│  K8s 原生组件（HPA/Deployment/Service/PVC）                   │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                 存储与数据层 (Storage & Data)                  │
│  PostgreSQL │ Redis │ S3 │ ClickHouse │ Kafka │ LanceDB      │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                   可观测性 (Observability)                    │
│  Prometheus + Grafana │ OpenTelemetry + Jaeger │ Loki        │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 控制面/数据面分离

| 维度 | 控制面 | 数据面 |
|------|--------|--------|
| **端口** | 8081 | 8080 |
| **职责** | 模型管理、端点管理、微调、计费 | 推理请求处理 |
| **扩缩容** | 独立副本数 | 独立副本数 |
| **故障隔离** | 管理接口 OOM 不影响推理 | 推理负载不影响管理 |

## 2. 技术选型

### 2.1 推理引擎层

| 组件 | 技术选型 | 选型理由 |
|------|---------|---------|
| LLM 推理 | **vLLM (v0.18+)** | PagedAttention、FlashAttention-4、连续批处理、投机解码 |
| 多模态推理 | **vLLM + SGLang** | SGLang 在多模态和结构化生成场景有更优吞吐 |
| 分布式编排 | **NVIDIA Dynamo** | PD 分离、KV-aware 路由、NIXL GPU 间 KV 直传 |
| 注意力内核 | **FlashAttention-4** | Blackwell 原生优化，1.3x cuDNN 提速 |
| MoE 通信 | **DeepEP** | MoE 专用通信库，仅激活专家 All-to-All 通信 |
| 国产 GPU | **vLLM-Ascend / LMDeploy** | 全面支持昇腾/寒武纪/海光，FP8+INT4 混合量化 |

### 2.2 后端服务层

| 组件 | 技术选型 | 选型理由 |
|------|---------|---------|
| API 服务 | **Go (Gin)** | 高并发低延迟，协程模型，静态编译 |
| 异步工作流 | **Temporal** | 可靠分布式工作流，内置重试/补偿 |
| 消息队列 | **Apache Kafka** | 高吞吐、持久化、消费者组 |
| 语义缓存 | **纯 Go 内存 + LanceDB(预留)** | LRU 淘汰，余弦相似度匹配 |
| A/B 测试 | **自研 Go 框架** | 流量分流、统计显著性计算 |

### 2.3 前端技术

| 组件 | 技术选型 | 选型理由 |
|------|---------|---------|
| Web 框架 | **React 19 + Next.js 15** | SSR + CSR，App Router |
| UI 组件 | **TailwindCSS** | 无 CSS-in-JS 运行时，深度定制 |
| 状态管理 | **Zustand 5** | 轻量全局状态 |
| 流式渲染 | **SSE** | 原生浏览器支持 |

### 2.4 存储方案

| 组件 | 技术选型 | 用途 |
|------|---------|------|
| 关系型数据库 | **PostgreSQL 16** | 用户/项目/模型/任务元数据 |
| 缓存 | **Redis 7 Cluster** | API Key 验证、速率限制 |
| 对象存储 | **S3** | 模型权重、数据集、Checkpoint |
| 分析数据库 | **ClickHouse** | 推理日志、计费明细分析 |
| AI 数据格式 | **Lance** | Data Lab 数据集底层存储 |
| 向量数据库 | **LanceDB** | 语义缓存、向量混合查询 |

### 2.5 基础设施与编排

| 组件 | 技术选型 | 用途 |
|------|---------|------|
| 容器编排 | **Kubernetes 1.30+** | GPU 集群统一编排 |
| GPU 虚拟化 (主) | **HAMi vGPU** | GPU 内存硬隔离 + 算力配额，多厂商统一抽象 |
| GPU 虚拟化 (辅) | **NVIDIA MIG** | H100/A100 硬件级强隔离，单卡最多 7 实例 |
| 调度器 (主) | **Volcano** | Gang Scheduling、Queue 隔离、优先级抢占 |
| 自动伸缩 | **KEDA + HPA** | 基于队列深度/GPU 利用率自动扩缩容 |

## 3. 核心数据流

### 3.1 推理请求数据流

```
Client Request (HTTPS)
  └─→ API Gateway (TLS 终止)
      ├─→ Auth Service → Redis 验证 API Key
      ├─→ Rate Limiter → Redis 滑动窗口计数器
      ├─→ Responses Adapter (仅 /v1/responses)
      │   ├─→ Items → Messages 转换
      │   ├─→ previous_response_id → 加载历史上下文
      │   └─→ 内置工具编排
      └─→ Model Router
          ├─→ 语义缓存检查 (LanceDB/内存，cosine > 阈值直接返回)
          ├─→ routing_key → 专属端点
          └─→ 模型名 → 共享推理集群
              └─→ Load Balancer → vLLM Worker (GPU)
                  ├─→ Prefill → Decode
                  ├─→ SSE Stream → Client
                  └─→ 异步写入 Kafka → ClickHouse + Billing
```

### 3.2 微调训练数据流

```
Client: POST /v1/fine_tuning/jobs
  └─→ Fine-tuning Service
      ├─→ 验证数据集格式
      ├─→ HAMi + Volcano 联合调度
      ├─→ 创建 VolcanoJob
      │   ├─→ 队列分配 + 优先级设置
      │   ├─→ Gang Scheduling (MinAvailable)
      │   └─→ TTL 清理
      ├─→ Volcano 调度到 GPU 节点
      │   ├─→ HAMi 分配虚拟 GPU
      │   ├─→ 拉取 Base Model + 数据集
      │   ├─→ 执行训练 (PyTorch + DeepSpeed/FSDP)
      │   └─→ Checkpoint → S3
      └─→ 状态轮询 → 注册模型 → Model Registry
```

## 4. 关键实现方案

### 4.1 多推理引擎路由

**实现位置**: `internal/engine/router.go`

```go
// 引擎选择优先级
// 1. 自定义引擎地址 (CUSTOM_ENGINE_<MODEL_ID>)
// 2. 数据库模型引擎配置 (models.engine_type)
// 3. 默认引擎 (环境变量 INFERENCE_ENGINE)
// 4. Mock 引擎 (降级)
```

**环境变量配置**:
```bash
INFERENCE_ENGINE=vllm|sglang|mock
VLLM_ENDPOINT=http://localhost:8000
SGLANG_ENDPOINT=http://localhost:30000
CUSTOM_ENGINE_deepseek-ai/DeepSeek-R1=http://custom:8000
```

### 4.2 语义缓存

**实现位置**: `internal/semcache/cache.go`

**工作流程**:
1. 请求到达 → 计算 prompt 向量 (调用 embedding 模型)
2. 余弦相似度匹配 → 相似度 ≥ 阈值 (默认 0.85) → 返回缓存
3. 未命中 → 正常推理 → 写入缓存

**配置**:
```bash
SEM_CACHE_ENABLED=true
SEM_CACHE_EMBED_MODEL=text-embedding-3-small
SEM_CACHE_THRESHOLD=0.85
SEM_CACHE_TOPK=3
```

### 4.3 S3 对象存储

**实现位置**: `internal/storage/s3store.go`

**策略**: S3 优先，失败回退 DB

```go
// 上传: S3 Upload → 成功则返回，失败则写入 DB
// 下载: S3 Download → 成功则返回，失败则从 DB 读取
// 删除: S3 Delete + DB Delete
```

**环境变量**:
```bash
S3_ENABLED=true
S3_ENDPOINT=http://minio:9000
S3_BUCKET=inference-platform
S3_ACCESS_KEY=xxx
S3_SECRET_KEY=xxx
S3_PATH_STYLE=true  # MinIO 需要 path style
```

### 4.4 HAMi GPU 虚拟化

**架构**:
```
Volcano Scheduler (调度决策)
       ↓
HAMi Device Plugin (资源抽象)
       ↓
GPU 节点池 (NVIDIA/昇腾/海光/寒武纪)
```

**关键资源声明**:
```yaml
resources:
  limits:
    nvidia.com/gpu: "1"
    nvidia.com/gpumem: "20480"    # GPU 内存 (MiB)
    nvidia.com/gpucores: "60"    # 算力配额 (%)
```

**调度策略**:
- `binpack`: 共享集群最大化利用率
- `spread`: 高可用隔离
- `topology-aware`: MoE 专家并行优化

### 4.5 Volcano 多集群调度

**实现位置**: `internal/volcano/multi_cluster.go`

**集群选择策略**:
1. 按区域/可用区过滤
2. 选择可用 GPU 最多的集群
3. 主集群兜底

**资源跟踪**:
```go
type ClusterUsage struct {
    ClusterName     string
    TotalGPUs       int
    AvailableGPUs   int
    TotalCPU        int64
    AvailableCPU    int64
    TotalMemoryMiB  int64
    AvailableMemMiB int64
    JobCount        int
    LastUpdated     time.Time
}
```

**跨集群提交**:
```go
job, clusterName, err := mcc.SubmitJobAcrossClusters(ctx, job, gpuCount, region, zone)
```

## 6. 部署方案

### 6.1 本地开发

```bash
# 1. 启动依赖
docker-compose up postgres redis -d

# 2. 启动后端
cd backend && go run ./cmd/server

# 3. 启动前端
cd frontend && npm install && npm run dev
```

### 6.2 Kubernetes 部署

```bash
# 1. 安装 HAMi
bash deploy/hami/install.sh

# 2. 安装 Volcano
bash deploy/volcano/install.sh

# 3. 部署平台
kubectl apply -f deploy/kubernetes/
```

## 7. 性能优化

### 7.1 推理优化技术

| 技术 | 说明 |
|------|------|
| PagedAttention | KV Cache 分页管理，减少显存碎片 |
| FlashAttention-4 | Blackwell 原生优化，1.3x cuDNN 提速 |
| 连续批处理 | 动态合批，请求即到即处理 |
| 投机解码 | 小模型预生成，大模型验证，加速 1.4-2x |
| KV Cache 压缩 | 3-bit KV 存储，6x 内存压缩 |
| 语义缓存 | 语义相似查询缓存，命中率提升 40-80% |

### 7.2 冷启动优化

| 策略 | 效果 |
|------|------|
| 模型权重节点预缓存 | 减少 60-80% 冷启动时间 |
| Warm Pool 预热副本 | 冷启动延迟 < 5s |
| 预测性扩容 | 消除可预测的冷启动 |

## 9. 监控与告警

### 9.1 指标体系

| 类别 | 指标 |
|------|------|
| 流量 | RPM、Input/Output TPM |
| 延迟 | E2E Latency、TTFT、TPS (P50/P90/P99) |
| 伸缩 | Active Replicas、GPU Utilization |
| 错误 | Error Rate by Status Code、429 Rate Limit |

### 9.2 告警规则

| 规则 | 阈值 | 通知渠道 |
|------|------|---------|
| GPU 利用率过高 | >90% | Webhook/邮件/钉钉 |
| GPU 利用率过低 | <50% | Webhook |
| 错误率异常 | >5% | Webhook/邮件 |
| 余额不足 | <10% | 邮件/控制台 |
