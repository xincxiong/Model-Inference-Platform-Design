## 一、产品概述

火山方舟是火山引擎推出的一站式大模型服务平台，旨在为企业提供从**模型接入、数据管理、微调训练、推理部署到应用编排**的全生命周期服务。平台深度整合了字节跳动内部多年大模型研发与业务落地经验（如豆包、抖音、飞书等），帮助企业以低门槛、高效率的方式构建专属 AI 应用。

### 核心定位
- **一站式 MaaS（Model as a Service）平台**
- 覆盖模型全生命周期：选型 → 推理 → 精调 → 部署 → 运维 → 应用编排
- 面向企业级客户与开发者双端用户
- 字节内部实践沉淀，经过亿级用户场景验证

## 二、核心功能模块

### 2.1 模型推理服务

#### 在线推理（三种服务等级）
| 服务类型 | 特点 | 适用场景 |
|:---|:---|:---|
| **在线推理（常规）** | 标准推理服务，平衡成本与性能 | 日常业务调用、通用场景 |
| **在线推理（低延迟）** | 优化首字延迟（TTFT），保障响应速度 | 实时对话、交互式应用 |
| **在线推理（TPM 保障包）** | 保障每分钟 Token 配额，防止突发限流 | 高并发、峰值流量场景 |

#### 批量推理
- 异步任务提交与回调机制
- 适用于离线数据处理、批量内容生成等场景
- 成本较在线推理更低

#### 模型单元管理
- **模型单元概述**：资源分配、计费与运维的基本载体
- **创建模型单元**：按需创建、配置配额
- **管理模型单元**：生命周期管理、监控与优化

#### 高级推理能力
- **智能模型路由**：根据请求复杂度、成本策略或性能要求，自动将流量分发至最优模型或推理节点
- **MLP 推理服务**：混合专家模型推理
- **自定义模型推理**：支持用户上传自有模型进行推理

### 2.2 模型精调与定制

#### 精调方式
| 精调类型 | 说明 | 适用场景 |
|:---|:---|:---|
| **SFT（有监督微调）** | 基于标注数据进行指令微调，支持 LoRA、QLoRA 等高效微调范式 | 垂直领域适配、任务特定优化 |
| **DPO（直接偏好优化）** | 基于对比数据进行偏好对齐，替代传统 RLHF 的轻量化训练流程 | 输出质量优化、风格对齐 |
| **强化学习（RLHF/PPO）** | 基于奖励模型或环境交互的强化学习范式，用于复杂决策与长链条任务优化 | 复杂决策、长链条任务 |

#### 精调工具链
- **精调 SDK**：
  - Python/CLI 调用示例
  - 任务创建/监控/停止接口
  - 模型导出与版本管理
  - 错误码处理

- **数据集格式规范**：
  - SFT：`messages` 字段规范（JSON/JSONL）
  - DPO：`chosen`、`rejected` 对比数据格式
  - RL：奖励模型训练数据格式
  - 数据清洗与上传要求

- **自定义模型管理**：
  - 精调后模型的版本管理
  - 发布上线与部署至在线推理服务
  - 权限控制与 API 接入
  - 生命周期管理

#### 数据回流
- 支持业务数据回流至训练数据集
- 形成"使用 → 收集 → 精调 → 部署"的闭环
- 数据标注、版本管理与效果评估

#### 可视化训练流水线
- 提供可视化训练界面
- 训练超参数配置
- 训练任务提交与效果评估
- 常见调优策略与避坑指南

### 2.5 高级特性与工程化

#### 上下文管理
- **上下文缓存（Context API）**：
  - **原理**：将固定系统提示词或历史对话进行服务端缓存，后续请求命中缓存时跳过重复的 KV Cache 计算
  - **优势**：显著降低首字延迟（TTFT）并节省输入 Token 成本
  - **功能**：缓存创建与更新（支持指定 TTL、最大 Token 容量）、缓存绑定（传入 `cache_id` 或 `context_id`）、缓存状态查询与手动清理
  - **计费**：按存储量或命中次数计费

- **文件输入（File API）**：长上下文文件上传与缓存联用

#### 输出控制
- **流式输出**：SSE 流式返回，优化交互体验与 TTFT（首字响应时间）
- **结构化输出（Beta）**：强制模型按指定 JSON Schema 等格式输出，便于程序解析
- **续写模式**：基于已有内容继续生成

#### 提示词工程
- Prompt 优解/生成/调优/管理
- 内置提示词模板库
- 变量管理、版本对比与效果评测工具
- 各模型系列配套提示词指南

## 三、产品架构设计

### 3.1 逻辑分层架构

```
[应用层] 控制台 / API / SDK / Agent 编排 / 行业解决方案
   ↓
[服务层] 模型路由 / 流量管控 / 计费计量 / 安全过滤 / 监控告警
   ↓
[模型层] 自研模型（豆包系列） / 开源模型适配 / 第三方商业模型 / 微调模型仓库
   ↓
[框架层] 分布式训练框架 / 推理加速引擎 / 显存优化 / 动态批处理 / 量化压缩
   ↓
[算力层] GPU/NPU 异构集群 / 弹性调度 / 网络优化（RDMA） / 存储加速（NVMe/对象存储）
```

### 3.2 架构特点
- **云原生底座**：基于火山引擎云原生技术构建
- **存算分离**：存储与计算独立扩展，提升资源利用率
- **弹性调度**：支持自动扩缩容，应对流量波动
- **混合精度训练与推理**：优化显存使用与推理速度
- **端到端可观测性**：全链路监控与指标追踪

### 3.3 技术架构详细分层

| 架构层级 | 核心组件/能力 |
|:---|:---|
| **接入层** | 标准化 API/SDK（Chat、Responses、批量、Bot应用）、多语言客户端、Coding Plan 个人版及主流 AI 工具集成（Claude Code, Trae, OpenCode 等） |
| **调度与优化层** | 智能模型路由、上下文缓存(Context API)、流式处理、突发流量限流优化、续写模式(Prefill Response) |
| **推理与计算层** | 在线推理集群（常规/低延迟）、TPM 保障包、模型单元管理、批量推理服务、多模态生成引擎 |
| **精调与数据层** | SFT/DPO/RL 训练流水线、自定义模型管理、数据集格式规范、数据回流与知识库构建 |
| **安全与治理层** | 安全互信方案、IAM 权限管控、分账最佳实践、控制台登录保持、模型发布/下线公告管理 |

## 八、与自建推理平台的对比分析

### 8.1 火山方舟 vs 自建平台

| 维度 | 火山方舟（MaaS） | 自建推理平台 |
|:---|:---|:---|
| **模型获取** | 内置丰富模型，开箱即用 | 需自行下载/采购模型 |
| **推理基础设施** | 云端托管，无需管理 GPU | 需自建 GPU 集群 |
| **精调能力** | 提供 SFT/DPO/RL 全链路，可视化训练流水线 | 需自行搭建训练流水线 |
| **多模态支持** | 原生支持图片/视频/3D 生成 | 需集成多个独立模型 |
| **智能路由** | 内置智能路由策略 | 需自行开发 |
| **上下文缓存** | 托管式 Context API | 需自行实现 KV Cache 管理 |
| **运维成本** | 低，平台托管 | 高，需专业运维团队 |
| **定制化程度** | 中等，受平台限制 | 高，完全可控 |
| **数据隐私** | 数据需上传至云端 | 数据完全本地化 |
| **成本结构** | 按量付费，适合中小规模 | 固定成本，适合大规模 |
| **生态集成** | 无缝集成火山引擎生态 | 需自行集成 |

### 8.2 适用场景建议

**选择火山方舟的场景**：
- 快速验证 AI 业务可行性
- 中小规模调用，不想投入基础设施
- 需要多模态能力但缺乏相关技术积累
- 希望快速接入成熟模型生态
- 需要全生命周期服务（推理 + 精调 + 部署）

**选择自建平台的场景**：
- 大规模调用，自建成本更低
- 对数据隐私有严格要求
- 需要高度定制化的推理策略
- 已有 GPU 基础设施和运维团队
